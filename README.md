# 校园食记 · Java 后端 Demo

面向对象程序设计三人组大作业的第一阶段：先完成可调用、可持久保存的后端核心，之后再连接前端。

## 运行

需要 JDK 17～27、PowerShell；当前开发环境为 JDK 27。首次构建需要联网下载 Maven 和依赖。

在 PowerShell 中运行：

```powershell
cd F:\beihang\JAVA\JAVA-practice
.\build.ps1 test
.\build.ps1 run
```

服务默认地址：`http://127.0.0.1:8080`。健康检查：`GET /api/health`。
使用 Ctrl+C 停止。首次启动自动创建默认用户、一个食堂、一个档口、三个菜品和两条体验记录。示例菜品没有假图片地址，可以通过上传接口添加照片。以后启动不重复插入示例数据。

启动后，打开**另一个 PowerShell 窗口**演示：

```powershell
cd F:\beihang\JAVA\JAVA-practice
.\scripts\demo.ps1
# 可选：同时演示真实照片上传（请替换成存在的文件）
.\scripts\demo.ps1 -PhotoPath 'F:\photos\lunch.jpg'
```

PowerShell 7 可以直接运行完整演示；脚本上传照片使用 Windows 自带的 `curl.exe`。

打包并运行：

```powershell
.\build.ps1 package
java -jar .\target\food-diary-0.1.0.jar
```

运行 JAR 时也应以项目根目录为工作目录。相对路径的数据文件、照片和日志会保存到当前工作目录。
IDEA 用户可直接导入 `pom.xml`，并把运行配置的工作目录设为项目根目录。

## 已实现

| 功能 | 接口能力 |
| --- | --- |
| 食堂、档口、菜品 | 新增、查询、修改、归档、恢复 |
| 菜品照片与价格 | JPEG/PNG 上传、浏览、删除；参考价格保存 |
| 四项评分 | 每次用餐可评味道、性价比、分量、推荐程度 |
| 个人记录 | 吃过记录、收藏、踩雷；用餐记录修改和删除 |
| 筛选 | 食堂、档口、关键词、预算上下限、口味、类别、标记、是否吃过 |
| 随机推荐 | 按筛选条件抽取，排除踩雷及不可用菜品 |
| 个人榜单 | 综合、味道、性价比、分量、推荐五种榜单 |
| 月度消费 | 总消费、用餐次数、平均每餐金额、逐日明细 |

## 业务规则

- 一餐可以有多个不同菜品；同一道菜多份使用 `quantity` 表达。
- `paidAmount` 是该行**全部份数的实付总额**，不是单价。例如两份共花 18 元：`quantity=2, paidAmount=18`。月度统计不再乘份数。
- 金额使用 `BigDecimal` 和数据库 `DECIMAL`，接口最多接受两位小数。
- 用餐时间为校园本地时间，格式 `yyyy-MM-dd'T'HH:mm:ss`。不能记录未来时间。
- 一次评价必须同时给出四项 1～5 的整数评分；不评价时 `rating=null`。
- 综合分先对一次评价的四项求平均，再对该菜的所有有效评价求平均；未评价不算零分。
- 榜单按未舍入的平均分降序、评价次数降序、菜品 ID 升序排列，展示保留两位小数。
- 收藏和踩雷互斥，可同时取消。标记不修改消费记录。
- 食堂、档口、菜品的 DELETE 表示归档；归档父级会让下属菜品暂时不可用，但不改写子级自身的归档状态。恢复父级不会意外恢复此前单独归档的菜品。
- 已归档菜品不参与推荐和新增用餐；已有历史记录仍可查、可改、可删，榜单和消费不因归档而丢失。
- 历史记录保存菜名和实付金额快照；以后菜品改名、涨价不修改历史。菜品不能直接转移到其他档口，档口不能转移到其他食堂。
- 重复提交新增用餐会产生两条记录；前端需防止重复点击。第一版没有网络重试幂等键。

## 多人扩展边界

这是**单人本地体验版**，所有请求使用服务端默认用户 1，没有注册登录功能。`user_id`、所有权查询以及 `CurrentUser` 接口已预留；客户端不能传入 userId 冒充身份。

后续需接入真实身份认证，再替换 `LocalCurrentUser`，并补充登录态和访问控制。当前服务仅绑定本机回环地址，不作为多人部署版。第一版菜单属于个人，尚未实现全校共享菜单。

## 文件结构

```text
src/main/java/cn/edu/campus/food/
  api/          HTTP 接口、请求校验
  domain/       不可变业务结果
  repository/   JDBC 查询、数据映射和持久化辅助
  service/      菜单、用餐、推荐、榜单、统计、照片、当前用户
  support/      统一错误处理、首次启动数据
src/main/resources/   配置与建表 SQL
src/test/             业务及真实 HTTP 集成测试
scripts/demo.ps1      可执行演示流程
docs/                 接口说明、课程对照与设计说明
data/                 本地数据库（启动后生成）
uploads/              上传照片（上传后生成）
logs/                 日志（运行后生成）
.tools/、.m2/         项目内构建工具和依赖缓存（不提交）
target/               构建产物（不提交源码包）
```

## 配置与常见问题

- 端口占用：运行前 `$env:PORT='8081'`；演示时加 `-BaseUrl 'http://127.0.0.1:8081'`。
- 图片支持真实 JPEG/PNG，单张最多 5MB、1200 万像素，不支持把其他文件改名伪装图片。
- 数据库被占用：确认没有同时启动两个使用相同数据目录的实例。
- 首次下载失败：检查网络，重新运行构建脚本；不需要全局安装 Maven。
- 测试使用独立内存数据库和临时图片目录，不会清空开发数据库。
- 当前列表在完成数据库筛选后于内存分页，适用于本课程 demo 的小数据量。大规模多人版应改为数据库分页并优化聚合查询。
- 如不需要初始化示例菜单，在第一次启动前于 `application.properties` 添加 `app.demo-data=false`。已生成数据不会被此开关删除。
- 故障响应带有 `errorId` 时，可在 `logs/food-diary.log` 查找对应日志；接口不泄露数据库异常或本机路径。
