# 课程对照与三人组阶段计划

依据：工作区《2026面向对象大作业要求.pdf》。本文件为实施记录，不替代正式提交文档。

## 已确认要求

- 申雪萍老师班以 Java 为主要开发语言。
- 接受 Spring Boot 等 Java 后端框架，允许合理使用第三方库。
- 框架代码、非 Java 代码不计入工作量。使用框架的项目不直接适用 3 人组 2k～3k 行参考标准，不能靠无意义空行、注释或冗余代码凑数。
- 不得提交与以往学期项目雷同的项目，Web 选题另有重复方向限制。
- 三人组需选组长，在 Patpat Online 组队，最终由组长提交。
- 评分：工作量 30%，中期检查 10%，最终答辩与展示 40%，文档 20%。
- PDF 注明最终 DDL：2026-12-27 23:59:59；中期具体时间地点待定。用户补充：中期介绍需要 PPT。
- 最终 ZIP：`组号-组名-作品名`。包含 `组号-作品名-项目代码`、开发文档 PDF、使用说明书 PDF、展示 PPT。
- 开发文档记录成员姓名学号、真实职责、分工权重（0.9～1.1，默认 1）、协作方式与项目介绍。
- 使用说明书包含运行环境、图文功能说明、常见错误与处理。
- 开展正常、边界、空输入和短时间较多网络请求的必要测试。

## 当前阶段

完成八项核心功能的单人接口 demo，保留用户归属。暂不制作正式中期 PPT；待核心演示流程稳定后，使用实际结果制作。暂无成员姓名、学号、组号及真实分工信息，不虚构填充。

三人分工可按下面范围协商，实际贡献应在后续开发中记录：

1. 菜单与图片：食堂、档口、菜品、图片、筛选。
2. 食记与数据：用餐、评分、标记、数据一致性及测试。
3. 推荐与展示：推荐、榜单、统计、后续前端整合及文档演示。

这些是建议分工，不是已经完成的成员贡献声明。开发协作建议使用 Git 保存可追溯的真实提交。

## 中期 PPT 建议结构

1. 选题与场景：校园吃饭选择困难，菜单和个人体验缺乏整理。
2. 功能范围：八项需求及三个前端页面的映射。
3. 面向对象与数据设计：分层职责、用户归属、餐与菜品的关系。
4. 当前实现：使用实际运行结果展示闭环，不能将计划描述为已完成。
5. 关键设计：实付与参考价分离、整餐事务、评分聚合、推荐过滤。
6. 三人真实分工、当前进度、下一阶段前端与多人扩展计划。

现场演示建议：创建菜单 → 收藏 → 记录一餐并评分 → 预算筛选 → 随机推荐 → 查看榜单与月度消费 → 踩雷后再次推荐。图片上传可准备一张本地菜品照片演示。

## 第三方依赖

- Spring Boot / Spring Framework：HTTP 服务、依赖管理、事务与 JDBC 支持。来源：https://spring.io/projects/spring-boot
- H2：嵌入式持久化数据库。来源：https://h2database.com/
- Hibernate Validator（由 starter 引入）：参数校验。来源：https://hibernate.org/validator/
- JUnit / AssertJ（测试依赖）：自动验证业务结果。来源：https://junit.org/ 、https://assertj.github.io/doc/
- Apache Maven：构建工具，脚本校验下载包 SHA-512。来源：https://maven.apache.org/

项目自行实现菜单业务、历史快照、推荐规则、评分聚合、消费统计与数据归属检查；不能将依赖库代码计算为本组独立开发工作量。
